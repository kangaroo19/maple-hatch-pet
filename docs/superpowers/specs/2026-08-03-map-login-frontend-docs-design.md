# MapLogin 프런트엔드 문서화 설계

## 목적

후속 Codex 세션이 `poc/map-login/`의 실행 가능한 PoC와 `docs/frontend/`의 기술 계약을 함께 읽고 실제 제품 프런트엔드의 MapLogin 렌더러를 구현할 수 있게 한다.

문서는 PoC 코드를 반복해서 해설하는 데 그치지 않고, 검증된 데이터 흐름과 렌더링 규칙, 제품 구현 시 유지할 계약과 재설계할 부분을 구분한다.

## 독자와 사실 기준

- 주 독자는 실제 제품 프런트엔드를 구현할 Codex다.
- 현재 `poc/map-login/` 구현이 동작에 관한 기준 자료다.
- 코드에서 확인할 수 없는 동작은 확정 사실로 기록하지 않는다.
- 원본 KMS 클라이언트에서 직접 검증하지 않은 공식은 근사 또는 공개 구현 기반이라고 명시한다.
- 문서와 PoC가 충돌하면 후속 Codex는 PoC 코드를 확인하고 문서를 함께 수정해야 한다.

## 문서 구성

### `docs/frontend/index.md`

문서 세트의 진입점이다. 후속 Codex가 읽을 순서, 관련 PoC 파일, 검증된 범위, 범위 밖 항목과 구현 전에 확인할 전제를 제공한다.

### `docs/frontend/map-login-renderer.md`

현재 PoC가 MapLogin 장면을 복원하고 렌더링하는 방법을 설명하는 기술 명세다. 다음 내용을 한 문서에 포함한다.

- WZ 배치 정보와 Canvas 에셋 추출 흐름
- `scene.json`의 주요 구조와 필드 의미
- UOL, `_inlink`, `_outlink` 처리
- 맵 좌표, 카메라와 세로 스크롤 계산
- 프레임 `delay`와 alpha 보간
- 배경 `type` 0~7의 타일링과 이동
- 배경과 오브젝트의 렌더링 순서
- 배율, DPR과 보이는 영역만 다시 그리는 방식
- 공개 MapRender 구현을 참고한 근사 공식과 알려진 한계

### `docs/frontend/implementation-guide.md`

후속 Codex가 PoC를 실제 제품 코드로 옮길 때 따를 작업 지침이다. 다음 내용을 포함한다.

- 그대로 유지할 데이터·렌더링 계약
- PoC에서만 허용된 단순화와 제품에서 재설계할 경계
- 권장 구현 순서
- 파일과 모듈의 책임 분리
- 완료 조건과 가벼운 검증 체크리스트
- 자동 카메라 이동, 첫 프레임 고정, 좌표계 혼동 등 흔한 실패 사례

## 문서 연결 방식

`index.md`는 나머지 두 문서와 `poc/map-login/README.md`로 연결한다. 세부 문서는 관련 PoC 파일을 저장소 상대 경로로 링크하며, 코드 줄 번호처럼 변경에 취약한 링크는 사용하지 않는다.

후속 Codex는 다음 순서로 읽는다.

1. `docs/frontend/index.md`
2. `docs/frontend/map-login-renderer.md`
3. `docs/frontend/implementation-guide.md`
4. `poc/map-login/`의 실제 구현

## 검증

별도 자동 테스트는 추가하지 않는다. 문서 작성 후 다음을 확인한다.

- 세 문서가 모두 존재하고 상호 링크가 유효하다.
- 언급한 파일과 함수가 현재 PoC에 실제로 존재한다.
- `scene.json` 필드와 기본값이 `extract.cjs` 출력과 일치한다.
- 배경 type, 프레임 선택, 좌표와 스크롤 공식이 `scene-utils.js`와 `app.js`에 일치한다.
