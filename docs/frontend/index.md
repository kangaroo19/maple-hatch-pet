# MapLogin 프런트엔드 구현 문서

- 상태: 구현 기준 확정 — PoC 기준 동작 포함
- 기준 구현: [`poc/map-login/`](../../poc/map-login/)

## 이 문서를 읽는 대상

이 문서 세트는 `poc/map-login/`에서 검증한 MapLogin WZ 장면을 실제 제품 프런트엔드로 옮길 후속 Codex를 위한 구현 계약이다. 사람을 위한 튜토리얼보다 다음 구현에서 유지해야 할 데이터 의미, 렌더링 규칙과 검증 조건을 우선한다.

문서만 읽고 PoC 코드를 생략하면 안 된다. 문서는 결정과 경계를 설명하고 PoC는 실행 가능한 기준 동작을 제공한다.

## 먼저 읽을 파일

다음 순서로 읽는다.

1. 이 문서에서 범위와 사실 기준을 확인한다.
2. [MapLogin 렌더러 기술 명세](./map-login-renderer.md)에서 추출 데이터와 브라우저 렌더링 계약을 확인한다.
3. [제품 구현 가이드](./implementation-guide.md)에서 실제 프로젝트로 옮기는 순서와 완료 조건을 확인한다.
4. [PoC README](../../poc/map-login/README.md)를 읽고 PoC를 실행한다.
5. [`extract.cjs`](../../poc/map-login/extract.cjs), [`scene-utils.js`](../../poc/map-login/public/scene-utils.js), [`app.js`](../../poc/map-login/public/app.js)를 직접 읽는다.

## 제품 UI 의도

MapLogin 장면을 추출한 목적은 구버전 로그인 화면을 기술적으로 재현하는 데 그치지 않고, Maple Hatch Pet의 실제 프론트엔드 UI 기반으로 사용하기 위해서다. 원본 장면의 공간과 감성을 유지하되 입력, 선택과 포커스는 접근 가능한 웹 컨트롤로 구현한다.

제품 UI는 너비 `1024px` 이상의 데스크톱 브라우저만 지원한다. 그보다 좁은 화면에서는 MapLogin 장면과 생성 UI를 축소하거나 재배치하지 않고 데스크톱 접속 안내를 표시한다.

### 전체 화면 흐름

1. 조회 전에는 사용자를 첫 로그인 화면에 고정하고 맵 최상단의 생성 영역으로 직접 스크롤하지 못하게 한다.
2. 앱 진입 시 보이는 첫 로그인 화면의 `Title/signboard/0` 패널 위치, 크기와 스타일은 유지한다. 기존 아이디 입력 영역 하나를 닉네임 입력에 사용하고, 원본 비밀번호 행은 시각적으로 비활성화한다. 실제 비밀번호 입력은 제공하지 않는다. 하단 STR/DEX/INT/LUK 현판과 두 번째 화면에는 로그인 UI를 배치하지 않는다.
3. 기존 `로그인` 버튼은 외형과 문구를 그대로 유지하되, 클릭과 Enter 제출은 NEXON 캐릭터 조회를 실행한다.
4. 로그인 버튼으로 시작한 조회에 성공하면 약 1초 동안 맵 최상단의 캐릭터 생성 영역으로 부드럽게 자동 스크롤한다. `prefers-reduced-motion` 사용자는 즉시 이동한다.
5. 초기 화면 설정 이후 카메라 전환은 로그인 제출 성공과 `다른 캐릭터 찾기` 활성화로만 시작한다. 생성 영역에서도 휠·터치·스크롤바를 통한 직접 스크롤은 허용하지 않는다.
6. 생성 영역에서 상태별 설정을 마치고 `Pet 만들기`를 누르면 같은 화면에서 생성한다.
7. 두 번째 화면의 양피지 아래에는 설치 명령 칸과 `명령어 복사`, `Codex에서 설치` 버튼을 항상 표시하고, 생성에 성공하면 같은 자리의 명령을 갱신한다. 별도 모달, 결과 페이지나 결과 URL로 이동하지 않는다.

여기서 조회 성공은 새 닉네임의 중복 여부를 확인한다는 뜻이 아니라, 입력한 닉네임으로 실제 메이플스토리 캐릭터를 찾았다는 뜻이다. 사용자가 상태별 설정을 마치면 제품 명세의 Pet 생성 단계로 이어진다. 상태와 선택 범위의 상세 계약은 [MVP PRD](../product-spec/mvp.md)를 따른다.

현재 PoC의 CSS 기반 로그인 폼은 접근성 흐름을 확인하기 위한 모의 UI이며 원본 로그인 패널의 시각 기준이 아니다. 제품은 KMS v1.2.43 `UI.wz/Login.img`에서 `Common/frame`(`800 × 600`), `Title/MSTitle`(`397 × 219`), `Title/BtLogin`의 `normal`·`mouseOver`·`pressed`·`disabled`(각 `95 × 48`), `Notice`, `NewChar`의 양피지·`charAlert`와 `Common/BtStart`(`125 × 52`) 자산을 추출하고 `UI.wz/Basic.img`에서 탭 조각을 추출한다. 상태 화살표, 액션·표정 선택기와 `Pet 만들기`는 외부 이미지 없이 Canvas로 직접 그린다. `MSTitle`은 버전 자산으로 유지하되 화면에는 표시하지 않는다. 제품 Canvas는 고정 `800 × 600` 논리 뷰포트로 로그인과 NewChar 편집 UI를 렌더링한 뒤 `Common/frame`을 카메라와 무관하게 합성하고, `다른 캐릭터 찾기` 버튼을 프레임 위에 합성한다. 추출 결과는 최종 앱의 `public/map-login/kms-v43/`에 버전된 정적 자산으로 포함한다.

로그인 입력과 버튼은 현재 장면의 `Title/signboard/0` bounds와 카메라 변환을 기준으로 배치한다. 빈 닉네임 입력에는 흐린 `캐릭터 닉네임` placeholder를 표시하고, 원본 비밀번호 행에는 반투명 비활성화 표현을 표시한다. 긴 닉네임은 입력 영역에 clip한다. 화면에 보이는 HTML input/button overlay는 만들지 않고, 화면 밖 native form은 한글 IME, 붙여넣기, 선택, Tab, Enter/Space와 접근성만 담당한다. 계정 저장, 회원가입, 비밀번호 찾기와 월드 선택처럼 제품 기능으로 연결되지 않는 버튼이나 컨트롤은 표시하지 않는다.

MapLogin 화면에는 별도 하단 바를 표시하지 않는다. 개인정보 처리 안내는 `/privacy`에서 제공한다.

### 캐릭터 생성 영역

- `NewChar/signboard/0` 좌표를 기준으로 조회한 캐릭터와 WZ 양피지 편집 UI를 같은 Canvas 장면에 표시한다. 화면에 보이는 HTML 캐릭터 카드나 편집 패널은 만들지 않는다.
- 원본 `Map.wz/Obj/login.img/NewChar/signboard/0`의 좌표 메타데이터는 편집 UI 배치 기준으로 유지하되, Codex 상태·액션·표정 UI와 겹치는 기존 스탯 선택판 이미지는 장면에 렌더링하지 않는다.
- 처음에는 `기본` 상태를 선택한다.
- 9개 상태는 비순환 좌우 화살표로 한 상태씩 이동한다. 화살표는 WZ 에셋 없이 Canvas로 직접 그리고 hover·pressed·disabled 상태를 색으로 구분하며, 제목은 영문 내부 상태명 없이 `기본 · 1/9` 형식으로 표시한다.
- 현재 상태의 액션과 표정은 WZ 에셋 없이 Canvas로 직접 그린 반폭 선택기로 고른다. 각 선택기는 기존 `202px` 영역의 왼쪽 `101px`를 사용하고, 오른쪽 `101 × 45px` 영역 중앙에는 `Login.img/NewChar/dice`의 첫 프레임을 원본 크기로 표시한다. 달리기 두 상태의 액션 목록은 `걷기 1(A02)`·`걷기 2(A03)`만 제공하고 방향별로 독립 선택한다. 주사위를 클릭하면 WZ origin을 유지한 4프레임을 100ms씩 한 번 재생하고 첫 프레임으로 돌아오며, 달리기 두 상태도 `A02`·`A03` 중 걷기 액션과 표정을 각각 무작위 지정한다. 선택기는 밝은 베이지 그라디언트, 갈색 테두리와 직접 그린 화살표를 사용하고 hover·pressed·disabled·selected 상태를 색으로 구분한다. 목록은 최대 8행이며 클릭, 휠, 화살표 키, Enter와 Esc를 지원한다. 공식 코드는 UI에 노출하지 않고 내부 값으로 유지한다.
- 상태, 액션 또는 표정을 선택하면 별도 미리보기 카드 없이 왼쪽 캐릭터가 해당 조합의 애니메이션을 즉시 반복 재생한다.
- `running-left`와 `running-right`는 `걷기 1(A02)`·`걷기 2(A03)` 중 액션과 표정을 방향별로 독립 선택할 수 있다. 기본 액션은 `걷기 2(A03)`이다.
- `Pet 만들기`는 `112 × 30` 금장 우드 버튼을 Canvas로 직접 그리고 양피지 하단에서 `15px` 여백을 둔 `(scroll.x + 65, scroll.y + 120)`에 배치한다. 문구는 항상 `Pet 만들기`로 유지하고 요청 중에는 disabled 상태만 표시한다. `다른 캐릭터 찾기`는 `Login.img/Common/BtStart` 원본 버튼을 `800 × 600` 논리 viewport의 `(8, 429)`에 고정하고 프레임 위에 합성한다. 첫 로그인 화면에서는 disabled 상태를 표시만 하고 입력 대상으로 취급하지 않는다.
- 진입·이탈 시 원본 양피지 열림·닫힘 프레임을 한 번 재생한다. `다른 캐릭터 찾기`는 닫힘 뒤 캐릭터와 상태 설정을 초기화하고 약 1초 동안 로그인 화면으로 자동 스크롤한다. 모션 감소 설정에서는 최종 프레임과 목적지로 즉시 전환한다.
- 화면 밖 native 버튼과 `select`를 Canvas 상태와 동기화해 키보드와 스크린리더 입력을 제공한다.

| 내부 상태 | 표시 이름 |
|---|---|
| `idle` | 기본 |
| `running-right` | 오른쪽 달리기 |
| `running-left` | 왼쪽 달리기 |
| `waving` | 손 흔들기 |
| `jumping` | 점프 |
| `failed` | 실패 |
| `waiting` | 대기 |
| `running` | 실행 중 |
| `review` | 검토 |

### 생성 성공과 설치 명령

- 양피지 아래 `12px` 간격에 `266 × 98` 금장 우드 패널을 두고, 패널 안에 `242 × 38` 설치 명령 칸과 그 아래 8px 간격의 `112 × 30` `명령어 복사`, `Codex에서 설치` 버튼을 항상 표시한다. 패널 내부 요소는 WZ 자산 없이 Canvas로 직접 그리며 양피지와 시각적으로 연결하지 않는다.
- 생성 전에는 명령 칸에 안내 문구를 표시하고 두 버튼을 disabled로 둔다. 생성 성공 후 서버가 반환한 `installCommand` 전체를 두 줄로 표시하고 두 버튼을 활성화한다. `packageUrl`은 화면 텍스트나 다운로드 링크로 표시하지 않는다.
- `Codex에서 설치`는 `Install this pet: <installCommand>` 전체를 URI 인코딩한 `codex://new?prompt=...` 링크를 열어 새 Codex 작업의 입력창을 채우며, 자동으로 전송하지 않는다.
- 복사 성공 또는 실패는 버튼 문구를 잠시 `복사 완료` 또는 `복사 실패`로 바꾸고 접근 가능한 상태 영역에도 전달한다. 별도 제목, 만료·설치 안내, 삭제 요청 링크와 닫기 버튼은 표시하지 않는다.
- 설치 영역에는 ZIP 직접 다운로드 링크, `curl`·`unzip`과 운영체제별 수동 설치 절차를 제공하지 않는다.
- 생성 시각, 별도 결과 미리보기와 프레임 잘림·크기 차이처럼 발행을 막지 않은 판정은 성공 UI에 표시하지 않는다.
- 설치 영역은 닫기나 포커스 트랩 없이 항상 같은 위치에 유지한다. 좌우 화살표로 상태 미리보기만 전환해도 생성 결과를 유지한다.
- 액션이나 표정을 변경하거나 주사위로 전체 상태를 무작위화하면 현재 설정과 결과가 달라지므로 기존 설치 명령을 즉시 제거하고 재생성을 요구한다. 결과가 있는 상태에서 `Pet 만들기`를 다시 누르면 새 `petId`와 패키지를 발행하고 명령을 교체한다.
- 새로고침하거나 화면을 닫으면 성공 UI를 복원하지 않는다. 별도 결과 페이지, 보관함과 결과 재조회 URL은 제공하지 않는다.
- 생성된 스프라이트와 manifest는 고유한 Pet 패키지로 Vercel Blob 공개 저장소에 발행하되, 별도 설치 이력이나 메타데이터는 저장하지 않는다. 생성 패키지는 28일간 유효하고 최대 30일 이내 삭제한다.

### 조회와 공통 경고 상태

- 닉네임 조회 중에는 진행 문구를 표시하지 않고 `BtLogin/disabled`만 렌더링해 중복 제출을 막는다.
- 빈 닉네임은 `닉네임을 입력해 주세요.` Notice로 표시하고 닫은 뒤 닉네임 입력에 포커스를 복원한다.
- 캐릭터 조회, 이미지 수집, 생성 또는 패키지 저장처럼 현재 웹 흐름을 진행할 수 없는 오류는 `UI.wz/Login.img/Notice` 기반 공통 경고 다이얼로그로 표시한다. 명령 복사 실패와 프레임 잘림·크기 차이처럼 발행을 막지 않은 판정은 대상이 아니다.
- 다이얼로그는 `Notice/backgrnd/1`의 양피지 프레임과 경고 아이콘, `Notice/BtYes`의 확인 버튼 하나를 유지한다. 오류 문구는 이미지가 아니라 최대 세 줄의 한국어 plain text로 렌더링한다.
- 다이얼로그가 열리면 확인 버튼에 포커스를 두고 배경 UI를 비활성화한다. 확인 또는 `Esc`로 닫고 배경 클릭은 무시한다. 캐릭터 없음은 닉네임 입력으로, 일시적 서버 오류는 해당 실행 버튼으로 포커스를 복원해 원래 화면에서 다시 시도하게 한다.
- Notice manifest나 필수 PNG를 불러오지 못하면 Notice를 사용하지 않고 내부 오류 정보를 제외한 접근 가능한 일반 텍스트 오류 화면을 표시한다.

## PoC에서 검증된 범위

현재 PoC는 KMS v1.2.43의 `UI.wz/MapLogin.img`를 대상으로 다음 흐름을 검증했다.

- `@tybys/wz@1.7.1`과 `ZLZ.dll` 키로 `UI.wz`, `Map.wz`를 읽는다.
- `MapLogin.img`에서 전체 맵 크기와 배경·오브젝트 배치를 읽는다.
- `Map.wz/Back/login.img`, `Map.wz/Obj/login.img`에서 실제 Canvas 프레임을 추출한다.
- UOL, `_inlink`, `_outlink`를 따라가고 같은 원본 Canvas를 중복 추출하지 않는다.
- 프레임별 `delay`, `origin`, `a0`, `a1`을 포함한 `scene.json`을 생성한다.
- 브라우저가 개별 PNG와 `scene.json`을 읽어 Canvas에 장면을 합성한다.
- 사용자가 긴 맵을 직접 세로 스크롤하며, 고정된 스크롤 위치에서도 WZ 애니메이션과 이동 배경이 갱신된다.
- 배경의 반복·이동, 프레임 선택과 좌표 계산은 독립된 순수 함수로 가볍게 검증한다.

이 범위는 MapLogin 장면 렌더링 가능성을 증명한다. 범용 메이플스토리 맵 렌더러나 원본 로그인 클라이언트 전체를 증명하지는 않는다.

## 제품 구현에 고정된 자산 계약

- v43 WZ 추출 결과인 scene, Notice·NewChar manifest와 PNG를 최종 앱의 `public/map-login/kms-v43/`에 커밋하고 Next.js 정적 자산으로 제공한다.
- 제품 빌드나 Vercel 배포 중에 원본 WZ를 다시 읽지 않는다. 원본 WZ와 DLL은 저장소 밖 읽기 전용 입력이다.
- scene, manifest와 PNG는 같은 버전 경로에서 원자적으로 갱신한다.
- `Common/frame`은 `800 × 600` 고정 화면에서 장면과 편집 UI 다음에 표시하고, viewport 고정 `다른 캐릭터 찾기`를 그 위에 합성한다. 첫 로그인 화면에서는 disabled 상태만 표시하고 두 번째 화면에서만 상호작용한다. `MSTitle`은 자산으로 유지하되 표시하지 않는다. 첫 로그인 화면의 `Title/signboard/0` 패널에는 `BtLogin` 4상태와 Canvas 입력을 장면·카메라 좌표로 배치한다.
- `new-char.json`은 `formatVersion: 7`이며 `NewChar` 양피지·`charAlert`·`dice` 4프레임, `Basic.img` 탭 조각과 `Login.img/Common/BtStart` 버튼의 출처, 크기, origin과 delay를 고정한다. Canvas 기반 상태 화살표, 액션·표정 선택기와 `Pet 만들기`는 런타임에서 외부 이미지 없이 그린다.
- 비기능 계정 컨트롤은 만들지 않는다.
- WZ 추출 자산을 비상업 Production에서 공개 제공하는 권리는 별도로 확인되지 않았다. 사용자는 이 위험을 인지하고 MVP 전제로 수용했으며, 이는 법적 허가나 권리 확인을 뜻하지 않는다.

## 구현 중 선택 가능한 범위

다음 항목은 위 제품·자산 계약을 바꾸지 않는 범위에서 구현자가 정할 수 있다.

- Canvas 렌더러를 단일 컴포넌트로 둘지 계산·에셋·스크롤 경계로 나눌지
- 초기 로딩, 일부 에셋 실패, manifest 버전 불일치의 사용자 경험
- 저사양 기기에서 DPR 상한, 프레임 갱신 빈도와 보이는 영역 최적화
- MapLogin 외 다른 WZ 맵까지 지원할지

이 선택이 사용자에게 보이는 계약을 바꾸면 문서와 구현을 함께 갱신한다.

## 사실 기준

- 저장소에 체크인된 `poc/map-login/`이 실행 동작의 기준이다.
- `scene.json` 계약은 [`extract.cjs`](../../poc/map-login/extract.cjs)가 실제로 쓰는 필드를 기준으로 한다.
- 렌더링 공식은 [`scene-utils.js`](../../poc/map-login/public/scene-utils.js)와 [`app.js`](../../poc/map-login/public/app.js)를 기준으로 한다.
- 이동 배경의 속도 공식은 공개된 WzComparerR2 MapRender를 참고한 근사다. 원본 KMS 바이너리에서 직접 검증한 공식으로 취급하지 않는다.
- 문서와 코드가 충돌하면 PoC를 실행해 동작을 확인하고 코드와 문서를 같은 변경에서 정렬한다.
- 원본 WZ 파일은 저장소 자산이 아니며 읽기 전용 입력이다.
