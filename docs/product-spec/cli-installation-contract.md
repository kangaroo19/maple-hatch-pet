# Maple Hatch Pet CLI 설치 계약

- 상태: 구현 기준 확정
- 최종 수정: 2026-08-16
- 관련 문서: [Pet 설치 사용자 계약](./installation-contract.md), [Pet 생성 흐름](./pet-generation-flow.md)

## 1. 목적과 명령

이 문서는 Maple Hatch Pet CLI의 패키지, 다운로드, 검증, 로컬 설치와 오류 계약을 정의한다.

- npm 패키지: `maple-hatch-pet`
- 실행 바이너리: `maple-hatch-pet`
- 지원 명령: `npx maple-hatch-pet add <petId>`
- `petId`: 서버가 생성마다 발급하는 소문자 UUID 문자열

MVP는 `add` 외 목록·검색·업데이트·삭제 명령과 `--force` 옵션을 제공하지 않는다. 같은 `petId`의 재설치는 옵션이나 확인 없이 안전한 교체로 처리한다.

## 2. 패키지 계약

서버는 `<petId>.codex-pet.zip`을 발행한다. ZIP 루트에는 다음 두 일반 파일만 존재해야 하며 디렉터리와 추가 엔트리는 허용하지 않는다.

```text
pet.json
spritesheet.png
```

`pet.json`은 UTF-8 JSON이며 정확히 다음 스키마를 사용한다.

```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "displayName": "천짱",
  "description": "<world> <class> 캐릭터",
  "spriteVersionNumber": 1,
  "spritesheetPath": "spritesheet.png"
}
```

- `id`는 요청한 `petId`, Blob 객체 이름과 설치 디렉터리 이름에 모두 일치해야 한다.
- `displayName`은 공백이 아닌 문자를 포함하는 문자열이다.
- `description`은 문자열이며 UI 표시 외 설치 판단에 사용하지 않는다.
- `spriteVersionNumber`는 숫자 `1`이다.
- `spritesheetPath`는 상대 파일명 `spritesheet.png`로 고정한다.
- 알 수 없는 필드, 중복 JSON 키와 타입이 다른 값은 거부한다.

`spritesheet.png`는 투명 배경 PNG, 정확히 `1536 × 1872`, 최대 20 MiB, 8열 × 9행의 v1 시트여야 한다. 압축된 ZIP 응답과 압축 해제한 전체 엔트리 크기는 각각 25 MiB를 넘지 않는다.

## 3. 다운로드 계약

CLI는 패키지에 내장된 고정 Production 서비스 origin의 다음 경로만 요청한다.

```text
GET /api/pets/<petId>/package
```

CLI는 사용자 입력, 응답 본문, 리다이렉트 또는 환경변수로 origin을 바꾸지 않는다. HTTPS만 허용하고 리다이렉트는 거부한다. 응답은 `.codex-pet.zip` 바이트와 `application/zip` 콘텐츠 타입을 사용한다.

서버는 DB 없이 `pet-packages/<petId>.codex-pet.zip`이라는 Vercel Blob 객체 키를 결정적으로 계산한다. `petId`와 객체 키의 대응을 별도 테이블에 저장하지 않는다. 생성 패키지는 28일간 유효하고 최대 30일 이내 삭제한다.

| HTTP | 의미 | CLI 처리 |
|---:|---|---|
| 200 | 패키지 반환 | 크기 제한을 적용하며 임시 위치에 저장하고 검증한다. |
| 400 | UUID 형식이 잘못됨 | 입력 오류로 종료한다. |
| 404 | 패키지가 만료되었거나 존재하지 않음 | 웹에서 다시 생성하라고 안내한다. |
| 503 | 저장소를 일시적으로 사용할 수 없음 | 기존 설치를 보존하고 재시도를 안내한다. |

다른 상태, 잘못된 콘텐츠 타입, 응답 크기 초과와 연결 중단은 다운로드 실패로 처리한다. 오류 응답은 [Pet 생성 흐름의 공통 envelope](./pet-generation-flow.md#35-공통-오류)를 사용한다.

## 4. 설치 경로와 원자성

CLI는 Node의 `os.homedir()`, `os.tmpdir()`와 `path` API로 경로를 계산한다. Windows, macOS와 Linux의 홈 경로, 임시 경로와 구분자를 하드코딩하지 않는다.

```text
<user-home>/.codex/pets/<petId>/pet.json
<user-home>/.codex/pets/<petId>/spritesheet.png
```

1. `petId`를 검증한 뒤 운영체제 임시 디렉터리 아래에 이번 실행 전용 디렉터리를 만든다.
2. 패키지를 제한된 크기로 다운로드하고 임시 위치에서 ZIP과 두 파일을 모두 검증한다.
3. 신규 설치면 검증된 디렉터리를 최종 경로에 반영한다.
4. 같은 `petId`가 설치되어 있으면 기존 디렉터리를 같은 파일 시스템의 백업 경로로 옮긴 뒤 검증된 새 디렉터리를 최종 경로에 반영한다.
5. 교체 반영에 실패하면 새 디렉터리를 제거하고 기존 디렉터리를 복원한다.
6. 성공 후 백업과 임시 산출물을 정리한다.

다운로드, 압축 해제 또는 검증이 실패한 경우 최종 경로를 건드리지 않는다. 최초 설치 실패는 부분 디렉터리를 남기지 않고, 재설치 실패는 기존 설치를 보존한다.

## 5. 보안 검증

CLI는 최종 경로에 반영하기 전에 다음을 모두 확인한다.

- ZIP 엔트리는 정확히 `pet.json`과 `spritesheet.png` 두 일반 파일이다.
- 엔트리 이름에 빈 값, 절대 경로, `..`, 역슬래시, 드라이브 문자와 NUL 문자가 없다.
- 디렉터리, 심볼릭 링크, 하드 링크와 기타 특수 파일 엔트리를 거부한다.
- 엔트리 개수, 압축 응답 크기, 각 파일과 압축 해제 총크기 제한을 초과하지 않는다.
- `pet.json` 스키마, UUID 일치, sprite version과 `spritesheetPath`를 검증한다.
- PNG 서명, 디코딩 크기, 투명 배경과 파일 크기를 검증한다.
- 네트워크는 고정 HTTPS origin만 사용하고 자격 증명과 로컬 경로를 전송하지 않는다.

검증 실패 원인이 된 외부 경로, 전체 응답 본문이나 로컬 임시 경로를 사용자 메시지와 원격 로그에 노출하지 않는다.

## 6. 출력과 종료 코드

| 종료 코드 | 의미 | 사용자 메시지 |
|---:|---|---|
| `0` | 최초 설치 또는 재설치 성공 | 설치 경로를 숨긴 채 최초 설치와 교체 설치를 구분하고 Pets 새로고침을 안내한다. |
| `2` | 명령 형식 또는 `petId`가 잘못됨 | `npx maple-hatch-pet add <petId>` 사용법을 표시한다. |
| `3` | 패키지 만료 또는 미존재 | 웹에서 Pet을 다시 생성하라고 안내한다. |
| `4` | 네트워크 또는 저장소 장애 | 기존 설치가 보존되었으며 잠시 후 재시도하라고 안내한다. |
| `5` | 패키지 또는 manifest 검증 실패 | 설치하지 않았고 패키지가 유효하지 않다고 안내한다. |
| `6` | 로컬 파일 시스템 반영 실패 | 부분 설치를 남기지 않았으며 기존 설치가 있으면 복원되었다고 안내한다. |
| `1` | 분류되지 않은 내부 오류 | 설치하지 않았으며 다시 시도해도 계속되면 문의하라고 안내한다. |

성공 메시지는 설치된 Pet의 `displayName`과 Pets 새로고침 절차를 포함한다. 실패 메시지는 기존 설치 보존 여부를 명확히 표시한다.

## 7. 완료 조건

- 패키지·바이너리 이름과 명령이 모두 `maple-hatch-pet` 계약과 일치한다.
- 유효한 패키지만 `<user-home>/.codex/pets/<petId>`에 설치된다.
- 같은 ID의 재설치는 검증 성공 후 교체되고 그 전의 실패는 기존 설치를 보존한다.
- 경로 순회, 절대 경로, 링크 엔트리, 용량 초과와 허용되지 않은 origin이 차단된다.
- 오류 종류가 정해진 종료 코드와 사용자 메시지로 구분된다.
