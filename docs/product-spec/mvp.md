# Maple Hatch Pet MVP PRD

- 상태: 구현 기준 확정
- 최종 수정: 2026-08-24
- 제품 형태: 로그인 없는 공개 웹서비스
- Pet 규격: Codex sprite v1

## 1. 제품 정의

Maple Hatch Pet은 공개된 메이플스토리 캐릭터 닉네임으로 현재 캐릭터 외형을 조회해 Codex Pet으로 만들고 설치할 수 있게 한다. 로그인이나 NEXON 계정 연동이 없으므로 조회한 캐릭터와 서비스 사용자의 소유 관계는 확인하거나 보증하지 않는다.

서비스는 NEXON Open API에서 캐릭터의 현재 외형과 공식 액션 프레임을 가져온다. AI 이미지 생성 없이 9개 Codex 상태의 애니메이션을 구성하고, Codex가 지원하는 v1 스프라이트 시트로 변환한다.

완성된 Pet은 UUID 기반 `petId`를 가진 `.codex-pet.zip`으로 발행한다. 같은 화면에서 `npx maple-hatch-pet add <petId>` 명령을 복사하고 로컬 터미널에서 실행해 설치한다.

## 2. 문제와 대상 사용자

### 문제

메이플스토리 캐릭터 외형을 Codex Pet으로 만들려면 API 조회, 상태별 프레임 선정, 스프라이트 시트 조립, 규격 검증과 로컬 설치를 직접 수행해야 한다. 일반 사용자가 하기에는 과정이 길고 Codex Pet 규격도 알아야 한다.

### 대상 사용자

- 공개된 메이플스토리 캐릭터 외형을 Codex Pet으로 쓰고 싶은 사용자
- 이미지 편집이나 로컬 파일 조작 없이 설치하기를 원하는 사용자

## 3. 목표

- 닉네임 입력만으로 현재 캐릭터를 찾는다.
- 공식 NEXON 이미지와 액션만으로 애니메이션 Pet을 만든다.
- 기본 설정을 제공하되 9개 상태에서 허용된 액션과 표정을 사용자가 조정할 수 있게 한다.
- 생성 결과마다 설치 식별자와 검증된 Pet 패키지를 발행하고 CLI 설치 명령을 복사할 수 있게 한다.
- NEXON API 키를 브라우저나 설치 패키지에 노출하지 않는다.

## 4. MVP 제외 범위

- 로그인, 회원 계정, 개인 보관함
- 갤러리, 검색, 추천, 인기 순위와 공개 탐색
- 외부 이미지 또는 사용자 제작 Pet 업로드
- AI 이미지 생성
- Codex sprite v2와 16개 시선 방향
- 메이플스토리 외 게임 또는 아바타 서비스
- 모바일 앱, 너비 `1024px` 미만의 웹 UI와 Codex 외 플랫폼
- ChatGPT 웹 업로드를 Maple Hatch Pet 설치 경로로 제공하는 기능
- Codex IDE 확장의 Pet 지원
- CLI의 목록, 검색, 업데이트와 삭제 명령
- ZIP 직접 다운로드, `curl`·`unzip`과 운영체제별 수동 설치 절차
- 보관 기간을 사용자가 설정하는 관리 UI

생성 결과를 다시 여는 결과 페이지, 공개 목록과 보관함은 제공하지 않는다. `petId`는 패키지 다운로드와 로컬 설치를 연결하는 식별자로만 사용하며 설치 이력이나 별도 메타데이터 조회 기능은 제공하지 않는다.

## 5. 핵심 사용자 흐름

1. 사용자가 구버전 MapLogin 로그인 패널의 단일 입력창에 메이플스토리 캐릭터 닉네임을 입력하고 기존 `로그인` 버튼을 누른다.
2. 서버가 보유한 NEXON API 키로 OCID와 기본 정보를 조회한다.
3. 조회에 성공하면 화면이 맵 최상단의 생성 영역으로 이동하고 서비스가 캐릭터 이름, 월드, 직업, 레벨과 현재 외형을 표시한다.
4. 생성 영역 왼쪽에는 현재 캐릭터를, 오른쪽에는 9개 Codex 상태의 기본 액션과 표정을 적용한 편집 UI를 표시한다.
5. 사용자는 비순환 좌우 화살표로 9개 상태를 한 상태씩 이동하고, 상태별 액션과 표정을 변경하며 왼쪽 캐릭터에서 선택 결과를 즉시 확인한다.
6. 브라우저는 서버가 확인해 반환한 NEXON 정적 이미지 기반 URL로 애니메이션을 표시한다.
7. 사용자가 `Pet 만들기`를 누르면 서버가 설정을 정규화하고 v1 스프라이트 시트를 생성·검증한 뒤 `pet.json`과 함께 `.codex-pet.zip`으로 조립한다.
8. 서버가 UUID `petId`와 패키지를 발행하고 설치 명령과 28일 만료 시각을 반환한다.
9. 같은 Canvas 장면의 양피지 아래에 항상 표시되는 명령 칸을 생성 결과로 갱신하고 `명령어 복사`와 `Codex에서 설치` 버튼을 활성화한다.
10. 사용자가 명령을 복사해 로컬 터미널에서 실행하거나 `Codex에서 설치`로 새 Codex 작업을 열어 설치 요청을 전송한다.
11. CLI가 패키지를 검증해 로컬 Codex Pet 디렉터리에 설치하면 사용자가 ChatGPT 데스크톱 앱의 Pets 설정을 새로고침하고 설치한 Pet을 선택해 깨운다.

## 6. 상태와 기본 애니메이션

v1 시트의 9개 행을 다음 순서로 사용한다.

| 행 | 상태 | 기본 액션 | 기본 표정 | 규칙 |
|---:|---|---|---|---|
| 1 | `idle` | `A01` 기본 자세 2 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 2 | `running-right` | `A02` 걷기 1 | `E01` 윙크 | `A02` 걷기 1 또는 `A03` 걷기 2 선택 후 각 프레임을 좌우 반전 |
| 3 | `running-left` | `A02` 걷기 1 | `E01` 윙크 | `A02` 걷기 1 또는 `A03` 걷기 2 선택, 공식 하위 프레임 자동 반복 |
| 4 | `waving` | `A00` 기본 자세 1 | `E02` 웃음 | 공식 하위 프레임 자동 반복 |
| 5 | `jumping` | `A06` 점프 | `E10` 뽀뽀 | 공식 하위 프레임 자동 반복 |
| 6 | `failed` | `A34` 유령 걷기 | `E03` 울음 | 공식 하위 프레임 자동 반복 |
| 7 | `waiting` | `A11` 경계 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 8 | `running` | `A14` 휘두르기 1-2 | `E15` 더움 | 공식 하위 프레임 자동 반복 |
| 9 | `review` | `A12` 엎드려 찌르기 | `E09` 환호 | 공식 하위 프레임 자동 반복 |

기본값은 제품 설정이며 데이터 구조의 일부가 아니다. 이후 기본값이 바뀌어도 이미 생성된 설정의 의미는 바뀌지 않는다.

### 사용자 상태와 행의 관계

Codex가 사용자에게 표시하는 네 가지 활동 상태는 다음 행에 대응한다.

| 사용자 상태 | 스프라이트 행 |
|---|---|
| Running | `running` |
| Needs input | `waiting` |
| Ready | `review` |
| Blocked | `failed` |

`idle`, `running-left`, `running-right`, `waving`, `jumping`은 렌더러가 사용하는 보조 애니메이션 행이다. 정확한 재생 시점은 공개 계약으로 단정하지 않고 ChatGPT 데스크톱 앱에서 검증한다.

### 사용자 설정 범위

- `idle`, `waving`, `jumping`, `failed`, `waiting`, `running`, `review`: 액션과 표정을 모두 선택할 수 있다.
- `running-left`, `running-right`: `A02` 걷기 1 또는 `A03` 걷기 2를 방향별로 독립 선택하고 표정도 선택할 수 있다. 기본값은 `A02`와 `E01`이다.
- 일반 상태의 액션은 NEXON 공식 코드 `A00`부터 `A41`까지 제공하고, 달리기 상태는 `A02`·`A03`만 제공한다.
- 표정은 NEXON 공식 코드 `E00`부터 `E24`까지 제공한다.
- 코드, 공식 영문명, 한국어 표시명과 프레임 범위는 버전 `1`의 [액션·표정 카탈로그](./action-emotion-catalog.md)를 따른다. UI에는 한국어 표시명만 노출한다.
- 선택한 액션에 공식 하위 프레임이 있으면 프레임 번호 순서대로 자동 반복한다.
- 표정은 하위 프레임 유무와 관계없이 명시적인 0번 프레임만 사용한다. 예를 들어 `E06` 선택은 모든 액션 프레임에 `E06.0`을 적용한다.
- `running-right`는 `running-left`와 동일한 프레임 타이밍을 사용하고 각 프레임만 좌우 반전한다.

## 7. 기능 요구사항

### FR-1. 캐릭터 조회

- 사용자는 닉네임으로 캐릭터를 조회한다.
- 닉네임은 앞뒤 공백을 제거하고 빈 문자열만 거부한다.
- 서버는 NEXON Open API의 OCID 조회와 캐릭터 기본 정보 조회를 수행한다.
- 브라우저는 NEXON API 키를 받거나 NEXON Open API를 직접 호출하지 않는다.
- 성공 시 이름, 월드, 직업, 레벨과 서버가 허용된 호스트인지 확인한 현재 캐릭터 이미지 정보를 반환한다.

### FR-2. 상태 설정과 미리보기

- 조회 직후 9개 상태에 기본 설정을 적용한다.
- 사용자는 생성 전 모든 상태의 애니메이션을 확인할 수 있다.
- 사용자는 주사위 버튼으로 9개 상태의 편집 가능한 설정을 한 번에 무작위로 지정할 수 있다. 클릭하면 원본 주사위 4프레임을 한 번 재생하며, 일반 상태는 액션과 표정을, `running-left`와 `running-right`는 `A02`·`A03` 중 걷기 액션과 표정을 각각 독립적으로 무작위 지정한다.
- 액션, 표정 또는 전역 `무기 표시` 설정 변경은 서버가 반환한 공식 정적 이미지 기반 URL을 사용해 해당 상태 미리보기에 즉시 반영한다. 무기 표시는 기본 해제이며, 주사위와 상태 이동에서는 유지하고 새 캐릭터 조회와 초기화 때 해제한다. 무기 표시가 켜진 동안에는 실제 잘림 여부와 관계없이 화면 상단에 `큰 무기나 이펙트는 Pet에서 잘릴 수 있어요`라는 예방 안내를 표시한다.
- 미리보기 단계에서는 별도 서버 이미지 생성이나 픽셀 검증을 수행하지 않는다.
- 빈 프레임과 잘림 여부의 최종 판정은 `Pet 만들기` 이후 서버 생성 단계에서 수행한다.

### FR-3. 스프라이트 생성

- 생성에는 NEXON이 제공한 현재 캐릭터 이미지 URL과 공식 액션·표정 파라미터만 사용한다.
- 무기 표시는 사용자 선택이다. 기본 해제 시 `W04`로 무기를 제외하고, 체크 시 `W00`으로 장착 무기 타입의 기본 모션을 사용한다.
- 실제 디코딩한 원본 캔버스의 가로를 `576`픽셀로 정규화하고 모든 프레임에 같은 고정 scale과 anchor를 적용한다.
- 원본 anchor 비율 `x=0.5`, `y=0.7`을 `192 × 208` 셀의 `x=96`, `y=188`에 대응시키며, 액션이나 이펙트의 bounds로 캐릭터 크기를 다시 맞추지 않는다.
- 프레임별 원본 상대 위치를 유지해 점프 높이와 액션 고유의 위치 변화를 보존한다.
- 이펙트, 무기 또는 신체가 셀 밖으로 나가면 해당 픽셀을 자르며, 잘림 자체는 생성을 막거나 결과별 성공 UI 경고로 표시하지 않는다. 무기 표시 중의 상단 예방 안내는 픽셀 판정 결과가 아니다.
- 결과는 투명 배경의 PNG다.
- v1 결과물은 정확히 `1536 × 1872` 픽셀이다.
- 셀은 `192 × 208` 픽셀이며 8열 × 9행으로 배치한다.
- 파일 크기는 20 MiB를 넘지 않는다.
- 생성이 끝난 뒤 크기, 형식, 투명 배경과 파일 크기를 검증한 결과물만 공개한다.
- HTTP 요청이나 이미지 디코딩이 재시도 후에도 실패하거나 사용할 프레임이 완전히 비어 있으면 전체 생성을 차단한다.
- 일부 잘림이나 상태 간 크기 차이는 생성을 막지 않으며 성공 UI에는 표시하지 않는다.
- 사용자가 선택한 액션을 다른 액션이나 기본 자세로 자동 대체하지 않는다.

### FR-4. 데이터 최신성과 자산 보관

- 캐릭터 조회와 `Pet 만들기` 요청은 각각 NEXON에서 현재 정보를 조회하며, NEXON 조회 결과를 요청 사이에 캐시하지 않는다.
- 하나의 생성 요청 안에서 동일한 NEXON 이미지 URL 다운로드는 중복하지 않는다.
- 사용되지 않는 캐릭터 데이터를 갱신하기 위한 전수 백그라운드 재조회는 수행하지 않는다.
- 발행된 Pet 패키지는 자동으로 재생성하거나 외형을 변경하지 않는다.
- 최신 외형이 필요하면 사용자가 새 Pet을 생성하고 새 UUID `petId`와 패키지를 발급받는다.
- 검증된 PNG와 `pet.json`은 생성 결과마다 `.codex-pet.zip`으로 조립해 Vercel Blob 공개 저장소의 고유한 `pet-packages/<petId>.codex-pet.zip` 객체로 발행한다.
- 생성 패키지의 유효기간은 생성 시각부터 28일이며 성공 응답의 `expiresAt`으로 고정한다.
- 매일 실행하는 정리 작업이 28일 이상 된 `pet-packages/` 객체를 삭제하며, Vercel Hobby Cron의 실행 오차를 고려해 모든 생성 패키지를 최대 30일 이내 삭제한다.
- DB를 사용하지 않고 `petId`로 Blob 객체 키를 결정한다. 설치 이력과 별도 설치 메타데이터는 저장하지 않는다.

### FR-5. 생성 화면의 설치 명령

- 현재 상태 편집 UI의 NewChar 양피지 아래에 WZ 자산 없이 Canvas로 그린 금장 우드 패널을 두고 설치 명령 칸과 `명령어 복사`, `Codex에서 설치` 버튼을 항상 표시한다. 생성 전에는 안내 문구와 disabled 버튼을, 생성 성공 후에는 서버가 반환한 전체 설치 명령과 활성 버튼을 표시한다.
- 설치 영역에는 코드 칸과 두 설치 버튼 외의 제목, 만료·설치 안내, 이메일 링크와 닫기 버튼을 표시하지 않는다. `packageUrl`도 화면 텍스트나 링크로 표시하지 않는다. `Codex에서 설치`는 `Install this pet: <installCommand>`를 URI 인코딩한 `codex://new?prompt=...`를 열며 프롬프트를 자동 전송하지 않는다.
- 복사 성공 또는 실패는 버튼 문구를 잠시 `복사 완료` 또는 `복사 실패`로 바꾸고 접근 가능한 상태 영역에도 전달하며 알림을 중복해 쌓지 않는다.
- ZIP 직접 다운로드 링크와 수동 설치 절차는 제공하지 않는다.
- 생성 시각, 별도 결과 미리보기와 프레임 잘림·크기 차이처럼 발행을 막지 않은 판정은 성공 UI에 표시하지 않는다.
- 설치 영역은 닫기, 재열기와 포커스 트랩 없이 항상 같은 위치에 유지한다. `Pet 만들기` 문구는 생성 상태와 관계없이 유지하며 결과가 있을 때 다시 누르면 새 결과로 교체한다.
- 좌우 화살표로 상태 미리보기만 전환하면 생성 결과를 유지한다.
- 액션, 표정이나 무기 표시를 변경하면 현재 설정과 생성 결과가 달라지므로 결과와 설치 명령을 즉시 제거하고 재생성을 요구한다.
- 주사위로 전체 상태 설정을 변경해도 결과와 설치 명령을 즉시 제거하고 재생성을 요구한다.
- 다시 생성할 때마다 새로운 `petId`와 패키지를 발행한다.
- 별도 결과 페이지, 결과 URL, 보관함과 성공 상태 복원 기능은 제공하지 않는다. 새로고침하거나 화면을 닫으면 마지막 설치 명령을 복원하지 않는다.

### FR-6. CLI 설치

- 공식 설치 명령은 `npx maple-hatch-pet add <petId>` 하나다.
- 서버가 UUID `petId`, `packageUrl`, `installCommand`, `expiresAt`을 반환한다.
- CLI는 고정된 Production 서비스 origin의 다운로드 API에서 패키지를 받고 `<user-home>/.codex/pets/<petId>`에 설치한다.
- 같은 `petId`가 이미 설치되어 있으면 별도 확인이나 `--force` 없이 검증된 새 패키지로 교체한다.
- 새 패키지의 다운로드나 검증이 실패하면 기존 설치를 보존한다.
- 설치 성공 후 ChatGPT 데스크톱 앱의 Settings > Pets에서 Refresh하고 설치한 Pet을 선택하도록 안내한다.
- Node.js와 npm이 없는 사용자가 이 설치 흐름을 사용할 수 있다고 보장하지 않는다.
- ZIP 직접 다운로드와 운영체제별 수동 설치 절차는 제공하지 않는다.
- 사용자 흐름은 [설치 사용자 계약](./installation-contract.md), 패키지·검증·원자성·오류 코드는 [CLI 설치 계약](./cli-installation-contract.md)을 따른다.

Codex가 v2에서 사용하는 16개 look 방향은 NEXON 캐릭터 이미지 API가 제공하지 않는다. MVP는 NEXON 공식 이미지 전용·AI 미사용이라는 제품 약속을 유지하기 위해 일반적인 v2 Pet 제작 지침의 명시적 예외로 v1을 사용하며, v2용 방향 이미지를 추정하거나 생성하지 않는다.

### FR-7. NEXON 데이터 안내

- 서비스는 NEXON의 보증·제휴를 암시하지 않으며 NEXON Open API 데이터가 현 상태로 제공된다는 점을 안내한다.

## 8. 서비스 경계

MVP는 다음 책임을 분리한다.

| 영역 | 책임 |
|---|---|
| 웹 클라이언트 | 닉네임 입력, 설정 편집, NEXON 정적 이미지 기반 미리보기, 결과와 설치 수단 표시 |
| 웹 API | 캐릭터 조회, 설정 정규화, Pet 생성 요청, `petId` 발급, 패키지 발행·다운로드와 설치 명령 제공 |
| 생성기 | 공식 프레임 수집, 전체 bounds 기반 크기·anchor 보정, v1 시트 조립, `pet.json`과 ZIP 조립·검증 |
| 자산 저장소 | Vercel Blob 공개 저장소에서 생성 결과마다 고유한 Pet 패키지의 공개 HTTPS 제공과 기한 내 삭제 |
| CLI | 패키지 다운로드·검증, 운영체제 독립 경로 계산과 로컬 Codex Pet 디렉터리의 원자적 설치·교체 |

공개·내부 API 경로와 JSON 계약은 [Pet 생성 흐름](./pet-generation-flow.md#3-api-계약)을 따른다. 패키지와 로컬 설치는 [CLI 설치 계약](./cli-installation-contract.md)을 따른다.

## 9. 오류 처리

웹에서 현재 흐름을 진행할 수 없는 빈 닉네임·조회·이미지 수집·생성·패키지 저장 오류는 `UI.wz/Login.img/Notice` 기반 공통 경고 다이얼로그로 표시한다. 다이얼로그는 확인 버튼 하나만 제공하며 닫은 뒤 사용자는 원래 입력 또는 버튼으로 포커스를 복원해 다시 시도한다. 명령 복사 실패와 프레임 잘림·크기 차이처럼 발행을 막지 않은 판정에는 이 다이얼로그 계약을 적용하지 않는다.

| 상황 | 사용자 동작 |
|---|---|
| 닉네임이 비어 있음 | 입력 요청 문구를 표시하고 조회하지 않는다. |
| 캐릭터를 찾을 수 없음 | 닉네임과 조회 가능 시점을 확인하라는 메시지를 표시한다. |
| NEXON API 제한 또는 장애 | 잠시 후 다시 시도할 수 있는 오류로 표시한다. |
| 공식 이미지 요청 또는 디코딩 실패 | 제한된 재시도 후 생성을 차단하고 해당 상태와 프레임을 알려준다. |
| 사용할 프레임이 완전히 비어 있음 | 생성을 차단하고 다른 액션이나 표정을 선택하도록 안내한다. |
| 프레임이 잘리거나 크기가 불안정함 | 생성은 허용하며 성공 UI에는 표시하지 않는다. |
| 생성, 패키지 검증 또는 저장 실패 | Pet을 공개하지 않고 재시도 가능한 오류를 표시한다. |
| 설치 명령 복사 실패 | 화면의 명령을 직접 선택해 복사하도록 모달 안에서 안내한다. |
| 패키지 만료 또는 미존재 | 웹에서 Pet을 다시 생성해 새 명령을 받도록 안내한다. |
| CLI 다운로드·검증 실패 | 기존 설치가 보존되며 원인에 따라 재생성 또는 재시도를 안내한다. |

## 10. 보안과 운영 요구사항

- NEXON API 키는 서버 환경변수로만 관리하며 클라이언트 번들, 로그, 패키지와 설치 명령에 포함하지 않는다.
- 서버는 사용자 입력 URL을 가져오지 않는다. `character_image`는 정확히 `https://open.api.nexon.com/static/maplestory/character/look/` 경로 아래만 허용하며 리다이렉트를 따라가지 않는다.
- 서버는 허용된 원본 URL에서 필요한 `action`, `emotion`, `wmotion`, 크기와 좌표 파라미터만 다시 구성한다.
- 브라우저는 서버가 확인해 반환한 NEXON 정적 이미지 기반 URL만 미리보기에 사용한다.
- Vercel WAF에서 `POST /api/pets`를 IP당 10분에 3회로 제한하고, 하나의 생성 요청 안에서는 동일 이미지 다운로드를 중복하지 않는다.
- 패키지 응답은 올바른 콘텐츠 타입, 크기 제한, 캐시 정책과 HTTPS를 사용한다.
- CLI는 고정 Production origin만 사용하고 리다이렉트, ZIP 경로 순회, 절대 경로, 링크 엔트리와 용량 초과를 거부한다.
- 요청별 로그에는 처리 단계와 비밀이 아닌 오류 정보만 남긴다.
- 외부 모니터링 서비스는 도입하지 않는다. Vercel 함수·Cron·Blob 대시보드와 비식별 구조화 로그로 생성 실패와 정리 작업을 관찰한다.

## 11. 완료 조건

다음을 모두 충족하면 MVP 기능 구현이 완료된 것으로 본다.

- 유효한 메이플스토리 닉네임으로 현재 기본 정보와 외형을 조회할 수 있다.
- 캐릭터 소유권을 확인하거나 보증하지 않는 공개 조회 서비스임이 사용자에게 명시된다.
- NEXON API 키가 브라우저 네트워크 요청과 배포된 클라이언트 코드에 노출되지 않는다.
- 9개 상태의 기본 미리보기가 표시되고 허용된 상태 설정을 변경할 수 있다.
- 표정은 항상 0번 프레임을 사용하고 액션 하위 프레임만 반복한다.
- 빈 필수 프레임은 발행을 차단하며 일부 잘림과 크기 차이만 발행을 막지 않는 판정으로 허용한다.
- 결과 시트가 투명 PNG, `1536 × 1872`, 20 MiB 이하 조건을 통과한다.
- 생성 성공 후 같은 화면에 설치 명령과 복사·Codex 설치 버튼이 표시되고 별도 결과 페이지를 만들지 않는다.
- 생성 결과에 UUID `petId`, `packageUrl`, `installCommand`, `expiresAt`이 포함되고 ZIP 루트에는 계약과 일치하는 `pet.json`과 `spritesheet.png`만 존재한다.
- CLI가 유효한 패키지를 `<user-home>/.codex/pets/<petId>`에 설치하며 같은 ID 재설치 실패 시 기존 설치를 보존한다.
- NEXON 조회 결과를 요청 사이에 캐시하지 않고 조회와 생성 요청에서 현재 데이터를 사용한다.
- 기존에 발행한 패키지는 자동 변경하지 않으며 최신 외형 생성은 새 `petId`와 패키지를 사용한다.
- 생성 패키지는 28일간 유효하고 최대 30일 이내 삭제된다.
- 모든 화면에 NEXON 출처 문구가 표시된다.
- CLI 명령을 실제 설치 방식으로 제공하고 Codex 딥링크를 보조 진입점으로 제공하며, ZIP 직접 다운로드와 수동 설치 절차는 제공하지 않는다.
- Node.js와 npm이 없는 사용자의 CLI 설치는 보장하지 않는다.

## 12. 외부 의존성과 전제

- NEXON Open API가 캐릭터 OCID, 기본 정보와 공식 캐릭터 이미지 액션 파라미터를 계속 제공해야 한다.
- NEXON API와 캐릭터 이미지 사용은 NEXON Open API 이용약관, 최대 30일 TTL과 출처 표시 의무를 계속 준수해야 한다.
- Node.js와 npm이 설치되고 Production 서비스에 HTTPS로 접근할 수 있는 로컬 환경이 필요하다.
- npm 공개 레지스트리에 게시하기 직전에 `maple-hatch-pet` 패키지 이름의 사용 가능 여부를 다시 확인해야 한다.
- ChatGPT 웹 업로드와 Codex IDE 확장의 Pet 설치는 Maple Hatch Pet의 지원 범위가 아니다.
- Codex의 공개 Pet 규격이나 로컬 호환 계약이 바뀌면 생성기, 검증기, 패키지와 CLI를 함께 갱신해야 한다.
- 액션·표정 카탈로그는 서버에서 버전을 관리해 공식 API 변화가 기존 설정을 조용히 바꾸지 않게 한다.
