# Maple Hatch Pet MVP PRD

- 상태: 초안 — 제품 결정 반영 완료, 문서 리뷰 대기
- 최종 수정: 2026-07-25
- 제품 형태: 로그인 없는 공개 웹서비스
- Pet 규격: Codex sprite v1

## 1. 제품 정의

Maple Hatch Pet은 메이플스토리 캐릭터 소유자가 닉네임만으로 자신의 현재 캐릭터 외형을 Codex Pet으로 만들고 설치할 수 있게 한다.

서비스는 NEXON Open API에서 캐릭터의 현재 외형과 공식 액션 프레임을 가져온다. AI 이미지 생성 없이 9개 Codex 상태의 애니메이션을 구성하고, Codex가 지원하는 v1 스프라이트 시트로 변환한다.

완성된 Pet은 아래 두 경로로 같은 결과물을 설치한다.

- 기본 경로: `Codex에 설치` 딥링크
- 대체 경로: `npx maple-hatch-pet add <pet-id>`

## 2. 문제와 대상 사용자

### 문제

메이플스토리 캐릭터 외형을 Codex Pet으로 만들려면 API 조회, 상태별 프레임 선정, 스프라이트 시트 조립, 규격 검증과 로컬 설치를 직접 수행해야 한다. 일반 사용자가 하기에는 과정이 길고 Codex Pet 규격도 알아야 한다.

### 대상 사용자

- 현재 메이플스토리 캐릭터를 보유한 사용자
- 자신의 캐릭터 외형을 Codex Pet으로 쓰고 싶은 사용자
- 이미지 편집이나 로컬 파일 조작 없이 설치하기를 원하는 사용자

## 3. 목표

- 닉네임 입력만으로 현재 캐릭터를 찾는다.
- 공식 NEXON 이미지와 액션만으로 애니메이션 Pet을 만든다.
- 기본 설정을 제공하되 9개 상태에서 허용된 액션과 표정을 사용자가 조정할 수 있게 한다.
- 딥링크 한 번 또는 한 줄 `npx` 명령으로 설치할 수 있게 한다.
- 같은 캐릭터와 같은 설정에는 재사용 가능한 안정적인 Pet ID를 부여한다.
- NEXON API 키를 브라우저나 설치 패키지에 노출하지 않는다.

## 4. MVP 제외 범위

- 로그인, 회원 계정, 개인 보관함
- 갤러리, 검색, 추천, 인기 순위와 공개 탐색
- 외부 이미지 또는 사용자 제작 Pet 업로드
- AI 이미지 생성
- Codex sprite v2와 16개 시선 방향
- 메이플스토리 외 게임 또는 아바타 서비스
- 모바일 앱과 Codex 외 플랫폼
- Pet 만료, 삭제와 저장 기간 관리 UI

생성 결과는 공개 목록에 노출하지 않는 unlisted 방식이다. 결과 URL이나 Pet ID를 아는 사용자만 접근할 수 있다.

## 5. 핵심 사용자 흐름

1. 사용자가 메이플스토리 캐릭터 닉네임을 입력한다.
2. 서버가 보유한 NEXON API 키로 OCID와 기본 정보를 조회한다.
3. 서비스가 캐릭터 이름, 월드, 직업, 레벨과 현재 외형을 표시한다.
4. 서비스가 9개 Codex 상태에 기본 액션과 표정을 적용해 미리보기를 보여준다.
5. 사용자는 상태별 액션과 표정을 변경한다.
6. 선택한 액션 프레임이 비거나 잘릴 가능성이 있으면 미리보기에 경고를 표시한다. 생성 자체는 막지 않는다.
7. 사용자가 `Pet 만들기`를 누르면 서버가 설정을 정규화하고 Pet ID를 결정한 뒤 v1 스프라이트 시트를 생성·검증·저장한다.
8. 결과 화면은 Pet 미리보기, Pet ID, 딥링크 설치 버튼과 한 줄 CLI 명령을 함께 보여준다.
9. 사용자는 딥링크를 누르거나 CLI 명령을 실행해 설치한다.
10. 설치 후 Codex의 Pets 설정에서 새로고침하고 Pet을 선택한다.

## 6. 상태와 기본 애니메이션

v1 시트의 9개 행을 다음 순서로 사용한다.

| 행 | 상태 | 기본 액션 | 기본 표정 | 규칙 |
|---:|---|---|---|---|
| 1 | `idle` | `A01` 기본 자세 2 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 2 | `running-right` | `A03` 걷기 2 | `E00` 기본 | 왼쪽 걷기의 각 프레임을 좌우 반전 |
| 3 | `running-left` | `A03` 걷기 2 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 4 | `waving` | `A00` 기본 자세 1 | `E02` 웃음 | 공식 하위 프레임 자동 반복 |
| 5 | `jumping` | `A06` 점프 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 6 | `failed` | `A04` 엎드리기 | `E03` 울음 | 공식 하위 프레임 자동 반복 |
| 7 | `waiting` | `A07` 앉기 | `E05` 당황 | 공식 하위 프레임 자동 반복 |
| 8 | `running` | `A00` 기본 자세 1 | `E00` 기본 | 공식 하위 프레임 자동 반복 |
| 9 | `review` | `A00` 기본 자세 1 | `E05` 당황 | 공식 하위 프레임 자동 반복 |

기본값은 제품 설정이며 데이터 구조의 일부가 아니다. 이후 기본값이 바뀌어도 이미 생성된 설정의 의미는 바뀌지 않는다.

### 사용자 설정 범위

- `idle`, `waving`, `jumping`, `failed`, `waiting`, `running`, `review`: 액션과 표정을 모두 선택할 수 있다.
- `running-left`, `running-right`: 걷기 액션과 방향은 시스템이 고정하고 표정만 선택할 수 있다.
- 액션은 NEXON 공식 코드 `A00`부터 `A41`까지 제공한다.
- 표정은 NEXON 공식 코드 `E00`부터 `E24`까지 제공한다.
- 선택한 액션에 공식 하위 프레임이 있으면 프레임 번호 순서대로 자동 반복한다.
- `running-right`는 `running-left`와 동일한 프레임 타이밍을 사용하고 각 프레임만 좌우 반전한다.

## 7. 기능 요구사항

### FR-1. 캐릭터 조회

- 사용자는 닉네임으로 캐릭터를 조회한다.
- 닉네임은 앞뒤 공백을 제거하고 빈 문자열만 거부한다.
- 서버는 NEXON Open API의 OCID 조회와 캐릭터 기본 정보 조회를 수행한다.
- 브라우저는 NEXON API 키를 받거나 NEXON API를 직접 호출하지 않는다.
- 성공 시 이름, 월드, 직업, 레벨과 현재 캐릭터 이미지를 반환한다.

### FR-2. 상태 설정과 미리보기

- 조회 직후 9개 상태에 기본 설정을 적용한다.
- 사용자는 생성 전 모든 상태의 애니메이션을 확인할 수 있다.
- 액션 또는 표정 변경은 해당 상태 미리보기에 즉시 반영한다.
- 서버가 실제 공식 하위 프레임을 확인해 반복 순서를 구성한다.
- 빈 프레임, 비정상적으로 잘린 프레임 또는 상태 간 크기 차이는 경고로 표시한다.
- 경고가 있어도 사용자가 명시적으로 선택한 액션을 다른 액션으로 교체하거나 생성을 차단하지 않는다.

### FR-3. 스프라이트 생성

- 생성에는 NEXON이 제공한 현재 캐릭터 이미지 URL과 공식 액션·표정 파라미터만 사용한다.
- 무기 모션은 `W04`로 고정한다.
- 전체 상태에서 캐릭터의 시각적 크기와 바닥 기준선을 최대한 일정하게 맞춘다.
- 결과는 투명 배경의 lossless WebP 또는 PNG다.
- v1 결과물은 정확히 `1536 × 1872` 픽셀이다.
- 셀은 `192 × 208` 픽셀이며 8열 × 9행으로 배치한다.
- 파일 크기는 20 MiB를 넘지 않는다.
- 생성이 끝난 뒤 크기, 형식, 투명 배경과 파일 크기를 검증한 결과물만 공개한다.

### FR-4. Pet ID와 변형

- 같은 캐릭터도 서로 다른 상태 설정으로 여러 Pet을 만들 수 있다.
- Pet ID는 캐릭터의 정규화된 월드·닉네임과 정규화한 상태 설정의 해시로 결정한다.
- 같은 캐릭터와 의미상 같은 설정은 입력 순서와 무관하게 같은 Pet ID를 사용한다.
- 다른 설정은 다른 Pet ID를 사용한다.
- ID에는 닉네임 원문이나 API 키 같은 민감 값을 직접 포함하지 않는다.

정규화 대상은 9개 상태의 유효 설정이다. 시스템이 고정하는 걷기 액션과 방향도 해시 계산 전에 명시적인 값으로 포함해 생성 규칙 변경 시 충돌을 피한다.

NEXON 안내에 따라 OCID는 게임 콘텐츠 변경으로 바뀔 수 있으므로 안정적인 Pet ID의 직접 재료로 사용하지 않는다. 로그인이나 계정 연동이 없는 MVP에서는 닉네임 변경 또는 월드 이동 후의 캐릭터를 기존 캐릭터와 자동으로 연결하지 않으며, 새 캐릭터 정체성으로 취급한다.

### FR-5. 갱신과 보관

- 같은 캐릭터와 같은 설정으로 다시 생성하면 기존 Pet ID를 유지한다.
- 다시 생성하는 시점의 최신 메이플스토리 외형으로 해당 변형의 결과물을 갱신한다.
- 캐시 때문에 이전 이미지가 설치되지 않도록 실제 이미지 자산은 버전이 포함된 HTTPS URL로 발행한다.
- Pet 메타데이터는 안정적인 Pet ID에서 최신 자산 버전을 가리킨다.
- 보관 중인 NEXON 원본 정보는 마지막 성공 조회 후 30일이 지나기 전에 백그라운드에서 다시 조회한다.
- 자동 갱신으로 외형이 바뀌어도 Pet ID는 유지하고 새 자산 버전을 만든다. 이미 로컬에 설치된 Pet은 사용자가 다시 설치하기 전까지 자동 변경하지 않는다.
- MVP에서는 생성된 Pet과 결과 페이지를 기한 없이 보관한다.
- 삭제나 만료 기능은 제공하지 않는다.

### FR-6. 결과 페이지

- 결과 페이지는 다음 정보를 표시한다.
  - 캐릭터와 Pet 이름
  - Pet ID
  - 9개 상태 애니메이션 미리보기
  - 생성 시각 또는 자산 버전
  - `Codex에 설치` 버튼
  - 복사 가능한 `npx maple-hatch-pet add <pet-id>` 명령
- 결과 페이지는 검색이나 갤러리에 등록하지 않는다.
- Pet ID를 포함한 URL로 다시 열 수 있다.

### FR-7. 딥링크 설치

설치 버튼은 다음 공식 형식을 사용한다.

```text
codex://pets/install?name=<encoded-name>&imageUrl=<encoded-https-url>&description=<encoded-description>&spriteVersionNumber=1
```

- 모든 쿼리 값은 URI 인코딩한다.
- `name`은 공백이 아닌 문자를 한 개 이상 포함한다.
- `imageUrl`은 생성된 v1 시트의 절대 HTTPS URL이다.
- `spriteVersionNumber`는 명시적으로 `1`을 사용한다.
- 공식 허용 파라미터 외의 값을 추가하지 않는다.
- 딥링크 기능이 비활성화되었거나 지원되지 않는 환경을 위해 같은 화면에 CLI 설치 명령을 항상 표시한다.

### FR-8. 한 줄 CLI 설치

사용자는 다음 명령 하나로 설치할 수 있다.

```bash
npx maple-hatch-pet add <pet-id>
```

CLI는 다음 순서로 동작한다.

1. 서비스에서 Pet ID에 해당하는 메타데이터와 이미지 자산을 HTTPS로 조회한다.
2. Pet ID와 응답 메타데이터가 일치하는지 확인한다.
3. 이미지가 PNG 또는 WebP인지, 정확히 `1536 × 1872`인지, 20 MiB 이하인지 검증한다.
4. 임시 위치에 다운로드한 뒤 모든 검증이 성공한 경우에만 `~/.codex/pets/<pet-id>/`에 `pet.json`과 스프라이트 시트를 교체한다.
5. 기존 동일 ID가 있으면 검증된 새 파일로만 교체해 실패 시 기존 Pet을 보존한다.
6. 설치 완료 후 Codex Pets 새로고침 및 선택 방법을 출력한다.

CLI는 사용자가 제공한 임의 URL을 다운로드하지 않고 서비스가 Pet ID로 반환한 허용된 HTTPS 자산만 사용한다.

## 8. 서비스 경계

MVP는 다음 책임을 분리한다.

| 영역 | 책임 |
|---|---|
| 웹 클라이언트 | 닉네임 입력, 설정 편집, 미리보기, 결과와 설치 수단 표시 |
| 웹 API | 캐릭터 조회, 설정 정규화, Pet 생성 요청, 결과 메타데이터 제공 |
| 생성기 | 공식 프레임 수집, 크기·기준선 보정, v1 시트 조립과 검증 |
| 자산 저장소 | 버전이 포함된 스프라이트 시트와 Pet 메타데이터의 HTTPS 제공 |
| npm CLI | Pet ID 조회, 로컬 검증, 안전한 설치와 완료 안내 |

API의 구체적인 URL과 JSON 스키마는 구현 계획에서 정하되, 웹과 CLI가 동일한 Pet 메타데이터 및 이미지 자산을 사용해야 한다.

## 9. 오류 처리

| 상황 | 사용자 동작 |
|---|---|
| 닉네임이 비어 있음 | 입력 요청 문구를 표시하고 조회하지 않는다. |
| 캐릭터를 찾을 수 없음 | 닉네임과 조회 가능 시점을 확인하라는 메시지를 표시한다. |
| NEXON API 제한 또는 장애 | 잠시 후 다시 시도할 수 있는 오류로 표시한다. |
| 공식 이미지 프레임이 없음 | 해당 상태 미리보기에 경고하고 사용자의 재선택을 돕는다. |
| 프레임이 잘리거나 크기가 불안정함 | 해당 상태에 경고하되 생성은 허용한다. |
| 생성 또는 저장 실패 | Pet을 공개하지 않고 재시도 가능한 오류를 표시한다. |
| 딥링크가 동작하지 않음 | 같은 결과 화면의 CLI 명령을 안내한다. |
| CLI 다운로드 또는 검증 실패 | 로컬 기존 Pet을 보존하고 실패 이유를 출력한다. |

## 10. 보안과 운영 요구사항

- NEXON API 키는 서버 환경변수로만 관리하며 클라이언트 번들, 로그와 Pet 메타데이터에 포함하지 않는다.
- 서버는 사용자 입력 URL을 가져오지 않는다. NEXON 공식 응답에서 받은 허용된 HTTPS 호스트만 이미지 원본으로 사용한다.
- 캐릭터 조회와 이미지 프레임 요청에 캐시와 요청 제한을 적용해 NEXON API 키와 서비스 비용을 보호한다.
- 자산 응답은 올바른 콘텐츠 타입, 캐시 정책과 HTTPS를 사용한다.
- 로그에는 Pet ID, 처리 단계와 비밀이 아닌 오류 정보만 남긴다.
- NEXON API와 Codex Pet 규격 변경을 감지할 수 있도록 생성 실패율과 설치 자산 검증 실패를 관찰한다.

## 11. 완료 조건

다음을 모두 충족하면 MVP 기능 구현이 완료된 것으로 본다.

- 유효한 메이플스토리 닉네임으로 현재 기본 정보와 외형을 조회할 수 있다.
- NEXON API 키가 브라우저 네트워크 요청과 배포된 클라이언트 코드에 노출되지 않는다.
- 9개 상태의 기본 미리보기가 표시되고 허용된 상태 설정을 변경할 수 있다.
- 같은 캐릭터·같은 설정은 같은 Pet ID, 다른 설정은 다른 Pet ID를 만든다.
- 결과 시트가 투명 PNG/WebP, `1536 × 1872`, 20 MiB 이하 조건을 통과한다.
- 생성 결과 페이지를 Pet ID로 다시 열 수 있고 갤러리나 검색에 노출되지 않는다.
- 딥링크와 `npx maple-hatch-pet add <pet-id>`가 같은 자산 버전을 설치한다.
- CLI 설치가 중간에 실패해도 기존 동일 ID Pet을 손상하지 않는다.
- 최신 외형으로 재생성하면 Pet ID는 유지되고 새 자산 버전이 설치된다.
- 딥링크를 지원하지 않는 환경에서도 한 줄 CLI 설치 경로가 항상 보인다.

## 12. 외부 의존성과 전제

- NEXON Open API가 캐릭터 OCID, 기본 정보와 공식 캐릭터 이미지 액션 파라미터를 계속 제공해야 한다.
- NEXON API 및 캐릭터 이미지의 사용·캐시·재배포 조건을 출시 전에 확인해야 한다.
- NEXON Open API의 현재 안내는 가져온 데이터를 최소 30일마다 갱신하도록 요구하므로, 30일 재조회 작업은 출시 필수 운영 기능이다.
- Codex Pet 딥링크는 해당 기능이 활성화된 ChatGPT/Codex 데스크톱 환경에서만 동작할 수 있다.
- CLI 설치에는 Node.js와 npm/npx가 필요하다.
- Codex의 공개 Pet 규격이나 딥링크 계약이 바뀌면 생성기, 검증기와 설치 링크를 함께 갱신해야 한다.
- 액션·표정 카탈로그는 서버에서 버전을 관리해 공식 API 변화가 기존 설정을 조용히 바꾸지 않게 한다.
